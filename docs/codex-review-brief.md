## 依頼文（ここから下をコピーして Codex に貼る）

このリポジトリは **plamo-paint.com**（本番稼働中）のソースです。プラモデル・模型の「塗装レシピ」を
記録・共有する日本語サイトで、個人開発・オーナー1名（非エンジニア寄り）。まだSNSで大々的に告知していません。
これから告知するため、**告知に耐えるか**という観点で厳しくレビューしてください。

### 構成
- 静的HTML（ビルド無し）: `index.html`（アプリシェル）/ `legacy.html`（レシピ閲覧・編集）
- `worker/src/worker.js`: Cloudflare Worker。`/r/:id` にOGP+JSON-LD注入、sitemap、GitHub Pagesへのプロキシ
- Supabase: 認証・PostgreSQL・Storage・RLS・RPC（`supabase/schema.sql` + `migrations/001〜015`）
- Brevo（認証メール）/ Cloudflare（DNS・ドメイン）/ GitHub Pages（配信元）
- 規模: 登録3人・公開レシピ2件・**全て無料プラン**

### すでに対応済み（**再指摘は不要**。ただし「修正の不備・回避経路」の指摘は歓迎）
- Worker: `String.replace`の`$`置換による保存型XSS修正 / canonical注入 / ソフト404 / 内部ファイル遮断 /
  セキュリティヘッダ / cover_url検証 / origin障害時503 / publisher+logoのJSON-LD
- DB（migrations 001〜015）: created_at偽装遮断 / 通知爆撃抑制 / 閲覧数の上限と改ざん防止 / grid容量上限 /
  user_id形式 / profiles内部列の匿名遮断 / 退会時の画像削除 / **Storage匿名列挙の遮断** /
  投稿・下書きの画像同時削除RPC / 未参照画像の自動掃除 / BAN機能 / 検索RPCの軽量化 / 投稿レート制限 / pg_cron
- 自動テストが発見した Critical 2件も修正済み：
  (a) 匿名から他人の投稿を削除できた（`owner_id <> auth.uid()` がNULL比較で素通り）
  (b) BANされた本人が `banned_at` を消して自己解除できた
- フロント: 保存中の写真ズレ / 二重投稿 / セッション切れ / 不正gridの正規化 / アップロードMIME制限 /
  パスワード再設定画面 / 認証リンク切れの案内 / 架空データ(MOCK)廃止 / 縮小サムネ /
  SNSアプリ内ブラウザ検出と案内
- Google OAuth: 本番公開済み（誰でもログイン可）＋ブランド検証済み
- テスト: `tests/`（DB604本 + 画面28本 = 632本、全合格）

### すでに把握している未対応（**再指摘は不要**）
1. バックアップのGitHub Actions cronが60日で自動停止する
2. `supabase-js@2` の浮動バージョン指定
3. 塗料が配列の位置（`grid`の`c.i`）依存で、マスタを並べ替えると既存レシピの色が化ける
4. レシピ本文がJS描画のため検索エンジンに読まれない（SSR未対応）
5. メール登録の実地未検証
6. トップページに「何のサイトか」の説明が無い
7. 「人気の塗装方法」タイルが空で行き止まり
8. 障害検知・監視の仕組みが無い
9. 通報テーブルが投稿削除でCASCADE削除される
10. 配信元が `raw.githubusercontent.com`（GitHub Pagesに変更予定）

### レビューしてほしい観点（上記10件以外を重点的に）
**コードの中だけでなく、外から見た仕組み・運用・事業継続まで**見てください。過去の経験上、
重大な問題は「コードの外側」に潜んでいました（例：Googleログインがテスト状態のままで
誰も新規登録できなかった／SNSアプリ内ブラウザでGoogleログインが不可能だった）。

1. **RLS・トリガ・RPCの相互作用**：単体では正しいが組み合わせると破れる経路
2. **クライアントとDBの契約のズレ**：フロントが期待する形とDBが返す形の食い違い
3. **失敗時の挙動**：通信断・タイムアウト・部分保存・並行操作でデータが壊れる箇所
4. **無料枠の限界**：どの指標が最初に上限に達し、そのとき何が起きるか（数値で）
5. **モデレーション運用**：荒らし・違法投稿・権利侵害の申出に、個人1名で実際に対応できるか
6. **法務・表示**：日本の法令（個人情報保護法・特商法・景表法・プロ責法）とアフィリエイト表記
7. **データの一生**：作成→編集→削除→退会→バックアップで、消えるべきものが残る／残るべきものが消える箇所
8. **`migrations/015` 以降の修正そのものの妥当性**：新たなバグや副作用を作っていないか
9. **`tests/` のテスト自体の穴**：テストが通っているのに守れていない領域

### 出力の形式
各指摘について：
- **重大度**（Critical / High / Medium / Low）と、**告知前に直すべきか**（yes/no）
- **該当箇所**（`file:line`）
- **根拠**（実コードの引用。推測は「推測」と明記すること）
- **悪用手順または壊れる条件**（誰が何をすると、どう困るか）
- **推奨する修正**

**重要**：確実に実在するものだけを挙げてください。「念のため」の指摘は不要です。
逆に、上記「対応済み」の修正に**穴や回避経路**を見つけた場合は最優先で報告してください。
